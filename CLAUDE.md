# Working with me on this project

## How to give feedback
- Challenge my ideas. Don't sugarcoat problems.
- If something is a bad plan, say so plainly and explain why.

## Before big decisions
- Ask clarifying questions before making big decisions (for example: picking a framework, changing the site's structure, or adding a service).

## Keep it simple
- Prefer the fewest tools and dependencies that do the job.
- Don't add a library or build step unless it clearly earns its place.

## Explain in plain language
- I'm not a professional developer. Explain what you're doing and why in everyday words.
- Avoid jargon, or explain it briefly when you have to use it.

## Git
- Commit to git after each working change, with a clear message describing what changed.
